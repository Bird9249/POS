# UI — States & Feedback

อ้างอิง: [05 Architecture](../05-architecture.md) §4.5 · [Phase 7](../phases/07-harden-polish.md)

---

## 1) Network & Sync pills

| สถานะ | ข้อความตัวอย่าง | สี |
| --- | --- | --- |
| Online | ออนไลน์ | success/muted |
| Offline | ออฟไลน์ | warning |
| Syncing | กำลังซิงก์… | info |
| Pending | ออฟไลน์ · ค้าง 3 บิล | warning |
| Sync error | ซิงก์ไม่สำเร็จ · แตะเพื่อลองใหม่ | danger |

- แสดงที่ header เกือบทุกหน้า
- แตะแล้วเปิด sheet รายละเอียดคิว (รายการบิลค้าง, ปุ่ม Retry)

---

## 2) Empty states

| หน้า | ข้อความแนวทาง |
| --- | --- |
| ตะกร้าว่าง | สแกนหรือค้นหาสินค้าเพื่อเริ่มขาย |
| ไม่มีสินค้า | ยังไม่มีสินค้า — เพิ่มสินค้าแรก (Admin) |
| ไม่มีผลค้นหา | ไม่พบสินค้า |
| รายงานว่าง | ไม่มีรายการขายในช่วงเวลานี้ |

Empty state สั้นๆ 1 ประโยค + 1 ปุ่มหลัก (ถ้ามี action)

---

## 3) Error & validation

| กรณี | Feedback |
| --- | --- |
| บาร์โค้ดไม่พบ | toast/banner ทันที |
| เงินสดไม่พอ | ปุ่มยืนยัน disabled + ข้อความใต้ช่อง |
| ส่วนลดจนยอดติดลบ | กันที่ฟอร์ม + ข้อความสั้น |
| API error | banner + ปุ่มลองใหม่ |
| Offline บนหน้า online-only | แบนเนอร์เต็มความกว้าง: ต้องเชื่อมเน็ตเพื่อใช้หน้านี้ |

---

## 4) Loading
- หน้า list: skeleton แถวสั้น (ไม่ใช้ spinner เต็มจอนาน)
- ปุ่มบันทึก/ชำระ: แสดง loading ในปุ่ม
- Sync: ใช้ pill ที่ header ไม่บล็อกทั้งจอ

---

## 5) Success
- หลังขาย: หน้าสำเร็จชัด (ยอด/ทอน) แล้วค่อยพิมพ์
- หลังบันทึกสินค้า/ตั้งค่า: toast สั้น แล้วกลับ list หรืออยู่หน้าเดิม

---

## 6) สิ่งที่ต้องหลีกเลี่ยง
- Modal ซ้อนหลายชั้นตอนขาย
- ซ่อนสถานะ offline จนพนักงานไม่รู้ว่าบิลยังไม่ขึ้น server
- ใช้สีอย่างเดียวสื่อความหมายโดยไม่มีข้อความ (ร้านอาจจอไม่ดี/แสงจ้า)
