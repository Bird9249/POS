# 1. ระบบคิดเงินและออกใบเสร็จ (Checkout & Sales)

โมดูลหลักสำหรับพนักงานขายใช้คิดเงิน จัดการตะกร้า รับชำระ และออกใบเสร็จ

---

## 1.1 Search & Scan

### วัตถุประสงค์
ให้ค้นหาสินค้าได้เร็ว ทั้งแบบยิงบาร์โค้ดและพิมพ์ค้นหา

### ความสามารถ
- **ยิง Barcode** — สแกนแล้วเพิ่มสินค้าเข้าตะกร้าทันที (หรือโฟกัสรายการเดิมถ้ามีอยู่แล้ว)
- **ค้นหาด้วยข้อความ** — พิมพ์ชื่อสินค้า หรือรหัสสินค้า
- แสดงผลลัพธ์แบบเรียลไทม์ (ชื่อ, ราคาขาย, สต็อกคงเหลือ)

### กฎธุรกิจ
- สินค้าที่ไม่มีในระบบ / บาร์โค้ดไม่พบ → แจ้งเตือนชัดเจน
- **นโยบายสต็อก 0 (ล็อกแล้ว):** ขายได้ แต่ต้องเตือนพนักงาน (WARN) — ไม่บล็อกตะกร้า; server รับบิลได้แม้สต็อกติดลบเพื่อให้ sync ออฟไลน์ไม่ค้าง
- โฟกัสช่องค้นหา/สแกนควรรอรับอินพุตตลอดเวลาบนหน้า Checkout

### ข้อมูลที่เกี่ยวข้อง
| ฟิลด์ | คำอธิบาย |
| --- | --- |
| `barcode` | รหัสบาร์โค้ดสินค้า |
| `sku` / รหัสสินค้า | รหัสภายในร้าน |
| `name` | ชื่อสินค้า |
| `sell_price` | ราคาขาย |
| `stock_qty` | จำนวนคงเหลือ |

## 1.2 Cart Management

### วัตถุประสงค์
จัดการรายการขายก่อนชำระเงิน

### ความสามารถ
- **เพิ่ม** สินค้าเข้าตะกร้า
- **ลบ** รายการออกจากตะกร้า
- **เปลี่ยนจำนวน** (เพิ่ม/ลด)
- **ใส่ส่วนลด** แบบ:
  - เปอร์เซ็นต์ (`%`)
  - จำนวนเงิน (กีบ)

### ขอบเขตส่วนลด
| ระดับ | รายละเอียด |
| --- | --- |
| รายการ (Line discount) | ส่วนลดเฉพาะสินค้ารายแถว |
| ทั้งบิล (Bill discount) | ส่วนลดท้ายบิล (ถ้าต้องการรองรับ) |

### การคำนวณ
```text
ยอดรายการ = ราคาขาย × จำนวน − ส่วนลดรายการ
ยอดก่อนชำระ = ผลรวมยอดรายการ − ส่วนลดทั้งบิล
```

### กฎธุรกิจ
- จำนวนต้องมากกว่า 0
- ส่วนลดต้องไม่ทำให้ยอดติดลบ
- ส่วนลดแบบ `%` อยู่ระหว่าง 0–100
- เมื่อเปลี่ยนจำนวน/ส่วนลด ต้องอัปเดตยอดรวมทันที

## 1.3 Payment Methods (Manual)

ระบบรับชำระแบบ Manual ไม่ต่อ API ธนาคารในระยะแรก

### เงินสด (Cash)
- พนักงานกรอกจำนวนเงินที่ลูกค้าจ่าย
- ระบบคำนวณ **เงินทอนอัตโนมัติ**

```text
เงินทอน = เงินที่รับ − ยอดที่ต้องชำระ
```

- ถ้าเงินที่รับน้อยกว่ายอดที่ต้องชำระ → ไม่ให้จบการขาย

### โอนเงิน (Bank Transfer / BCEL One)
- แสดง **Static QR Code** (QR บัญชีร้าน) บนหน้าจอให้ลูกค้าสแกน
- พนักงานตรวจ Slip เอง แล้วกดยืนยันว่าได้รับเงินแล้ว
- ยังไม่ต่อ Bank API / Payment Gateway

### ข้อมูลที่ต้องมีตอนชำระ
| ฟิลด์ | คำอธิบาย |
| --- | --- |
| `payment_method` | `cash` หรือ `transfer` |
| `amount_due` | ยอดที่ต้องชำระ |
| `amount_received` | เงินที่รับ (กรณีเงินสด) |
| `change_amount` | เงินทอน (กรณีเงินสด) |
| `confirmed_by_staff` | พนักงานยืนยันแล้ว (กรณีโอน) |

## 1.4 Receipt Printing

### วัตถุประสงค์
ออกใบเสร็จรับเงินหลังขายสำเร็จ

### รูปแบบ
- Thermal Receipt ขนาด **80mm** หรือ **58mm**

### เนื้อหาในใบเสร็จ
- ชื่อร้าน
- เบอร์โทร
- วันที่ / เวลา
- บัญชีรายชื่อสินค้าและราคา
- วิธีชำระ
- ข้อความขอบคุณ

### ข้อมูลเสริมที่ควรมี (แนะนำ)
- เลขที่บิล / เลขอ้างอิงการขาย
- ชื่อพนักงานขาย (Cashier)
- ยอดรวม, ส่วนลด, ยอดสุทธิ
- เงินรับ / เงินทอน (ถ้าเป็นเงินสด)

### แหล่งค่าคอนฟิก
ดึงจาก **Receipt Configuration** ในโมดูลตั้งค่า (ชื่อร้าน, ที่อยู่, เบอร์โทร, Logo, เลขบัญชี)

---

## Flow การขาย (สรุป)

```text
1. ค้นหา/สแกนสินค้า
2. จัดการตะกร้า (จำนวน, ส่วนลด)
3. เลือกวิธีชำระ (เงินสด / โอน)
4. ยืนยันชำระ
5. ตัดสต็อกอัตโนมัติ
6. บันทึกการขาย
7. พิมพ์ใบเสร็จ
```

## สิทธิ์ผู้ใช้
| Role | สิทธิ์ในโมดูลนี้ |
| --- | --- |
| Admin | ใช้ได้ทั้งหมด |
| Cashier | คิดเงิน, ออกใบเสร็จ, ดูประวัติการขายของกะตนเอง |

## เกณฑ์สำเร็จ (Acceptance Criteria)
- [ ] สแกนบาร์โค้ดแล้วเพิ่มสินค้าเข้าตะกร้าได้
- [ ] ค้นหาด้วยชื่อ/รหัสได้
- [ ] เพิ่ม/ลบ/เปลี่ยนจำนวน และใส่ส่วนลด `%` หรือจำนวนเงินได้
- [ ] เงินสดคำนวณเงินทอนถูกต้อง
- [ ] โอนเงินแสดง Static QR และยืนยันแบบ Manual ได้
- [ ] พิมพ์ใบเสร็จ 80mm/58mm ได้ตามรูปแบบที่กำหนด
